## 헥사고날에 대한 사실과 오해       

### 계층형 아키텍처
- 서브 시스템을 계층(layers)으로 구조화 하는 스타일
- 상위 계층이 하위 계층을 사용하는 단방향 하향식 스타일
- 어떤 레이어의 변경이 다른 레이어 컴포넌트에게 되도록 영향을 주지 않음

### 3계층 아키텍처
- 전형적으로 사용하던 계층 이름
    - `UI` -> `Domain` -> `Data`
    - `Presentation` -> `Business Logic` -> `Persistence`
        - 여기서 `Business Logic` 레이어를 쪼개서 `Application Service` / `Domain` 으로 나눔
    
### 헥사고날 아키텍처
- 계층형 아키텍처처럼 단방향 비대칭이 아니라 대칭형 아키텍처
- 애플리케이션 내부와 외부 세계로 나눔
- 육각형이나 6개의 면 이런게 중요한게 아님
    - 대칭성을 강조하기 위해 육각형을 채용했을 뿐
- 헥사곤의 내부
    - 잘 변하지 않는 도메인 로직
        - 트랜잭션 스크립트로 구현되어 있던
        - 애플리케이션 서비스와 도메인 모델 로직으로 나누어져있던
- 헥사곤의 외부
    - 헥사곤과 상호작용하는 모든것 (Actor)
    - 사용자, 브라우저, CLI, 기계, 다른 시스템
    - 운영 환경, DB, 메시징
    - 테스트
- 헥사고날 아키텍처의 특징과 혜택
    - 테스팅 -> 운영 시스템에 연결되지 않고 애플리케이션 테스트가 가능해야 함
    - 애플리케이션과 상호작용하는 액터가 바뀌더라도 빌드하지 않고 테스트
    - UI 디테일이나 기술의 정보가 도메인 로직 안으로 노출되지 않도록 보호함 (반대도)
    - 외부의 연결이 다른것으로 변경 가능
